# 报关任务失败上报接口需求

## 1. 背景

财务电脑上的报关单下载 Agent 可能因为本地卡介质拔出、卡介质老化、读卡客户端异常、登录超时等原因，无法开始或继续下载。

现有任务上传接口：

```http
POST /api/customs/tasks/{task_id}/upload
Content-Type: multipart/form-data
```

要求必须提供 `files` 字段，只支持上传 PDF。实测发送“0 个文件 + 错误说明”时返回：

```http
HTTP 422
```

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "files"],
      "msg": "Field required",
      "input": null
    }
  ]
}
```

因此现有接口不能用于表达“卡介质无法读取”等非文件型业务失败。需要新增一个独立的任务失败上报接口。

## 2. 接口定义

### 2.1 基本信息

```text
方法: POST
路径: /api/customs/tasks/{task_id}/report-error
认证: Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
Agent 标识: X-Agent-Name: <配置中的 agent_name>
请求格式: application/json
成功状态码: 200 OK
```

正式环境 Base URL：

```text
http://47.96.9.22:8765
```

完整地址：

```text
http://47.96.9.22:8765/api/customs/tasks/{task_id}/report-error
```

### 2.2 路径参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | string | 是 | 服务器任务 ID，例如 `ct_63008f18bcaf4aa7` |

### 2.3 请求头

```http
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
X-Agent-Name: finance-pc-01
Content-Type: application/json
```

服务端必须同时校验：

1. Agent Token 有效。
2. `X-Agent-Name` 与请求体中的 `agentName` 一致。
3. 当前任务确实由该 Agent 领取。

### 2.4 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agentName` | string | 是 | 财务电脑稳定标识，应与 `X-Agent-Name` 一致 |
| `errorCode` | string | 是 | 稳定的机器可读错误码 |
| `message` | string | 是 | 可读错误原因，不得包含卡口令、Token、证书私钥等秘密 |
| `retryable` | boolean | 是 | 是否属于后续可能恢复的临时故障 |
| `reportedAt` | string | 是 | Agent 侧上报时间，ISO 8601 带时区 |
| `details` | object | 否 | 非敏感诊断信息，例如客户端错误码、任务阶段 |

请求示例：

```json
{
  "agentName": "finance-pc-01",
  "errorCode": "CARD_READ_FAILED",
  "message": "卡介质未连接或无法读取",
  "retryable": true,
  "reportedAt": "2026-10-29T13:24:33+08:00",
  "details": {
    "vendorErrorCode": "50070",
    "phase": "login"
  }
}
```

### 2.5 建议错误码

服务端应将 `errorCode` 作为稳定枚举保存，不要依赖 `message` 做业务判断。

| 错误码 | 含义 | 默认 `retryable` |
|---|---|---|
| `CARD_READ_FAILED` | 卡介质未插入、未被识别或读卡失败 | true |
| `CARD_SIGN_FAILED` | 卡介质证书私钥签名失败 | true |
| `LOGIN_TIMEOUT` | 单一窗口登录超时 | true |
| `BROWSER_LAUNCH_FAILED` | 浏览器或本地控件无法启动 | true |
| `DOWNLOAD_PARTIAL` | 部分报关单下载失败 | true |
| `DOWNLOAD_EMPTY` | 查询结果为空 | false |
| `UPLOAD_FAILED` | PDF 上传网络或服务端错误 | true |
| `INTERNAL_ERROR` | 其他未分类错误 | true |

新增错误码时应保持向后兼容，未知错误码不能导致服务端崩溃。

## 3. 响应定义

### 3.1 成功响应

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "taskId": "ct_63008f18bcaf4aa7",
  "state": "failed",
  "errorCode": "CARD_READ_FAILED",
  "message": "卡介质未连接或无法读取",
  "retryable": true,
  "errorReportedAt": "2026-10-29T13:24:35+08:00"
}
```

如果服务端希望保留“可恢复等待”语义，可以新增 `blocked` 状态，并返回：

```json
{
  "taskId": "ct_63008f18bcaf4aa7",
  "state": "blocked",
  "errorCode": "CARD_READ_FAILED",
  "message": "卡介质未连接或无法读取",
  "retryable": true,
  "errorReportedAt": "2026-10-29T13:24:35+08:00"
}
```

推荐规则：

- `retryable=true`：状态置为 `blocked`，等待人工恢复或重新执行。
- `retryable=false`：状态置为 `failed`。
- 如果不新增 `blocked` 状态，则两种情况都置为 `failed`，但必须保存 `retryable` 和错误码。

### 3.2 错误响应

| HTTP | 场景 | 服务端行为 |
|---|---|---|
| `400` | 请求体字段缺失或格式错误 | 返回具体字段错误 |
| `403` | Token 无效、Agent 名称不一致或非任务所有者 | 不修改任务 |
| `404` | 任务不存在 | 不创建新任务 |
| `409` | 任务已经 `completed`、`failed`，或不允许失败上报 | 返回当前状态 |
| `422` | Pydantic/FastAPI 参数校验失败 | 返回字段校验详情 |

## 4. 状态机要求

允许的失败上报转换：

```text
queued    -> 不允许（Agent 尚未领取）
claimed   -> blocked 或 failed
uploading -> blocked 或 failed
uploaded  -> 不允许（已接收完整 PDF 包）
processing -> 不允许（服务器已开始处理）
completed -> 不允许
failed    -> 幂等返回原失败信息
blocked   -> 幂等返回原阻塞信息
```

如果任务已过期或已被其他 Agent 重新领取，应返回 `409`，且不得覆盖新 Agent 的状态。

## 5. 幂等和并发

1. 同一任务、相同 `errorCode` 的重复上报应返回相同结果。
2. 同一任务第一次上报后，不允许另一 Agent 使用失败接口覆盖错误信息。
3. 失败上报和 PDF 上传必须互斥：
   - 只要存在有效的完整 PDF 上传，优先进入 `uploaded`。
   - 已进入 `uploaded`、`processing` 或 `completed` 后，失败上报返回 `409`。
4. 保存以下字段供后台查看：

```text
errorCode
errorMessage
errorRetryable
errorReportedAt
errorAgentName
errorDetails
```

## 6. curl 示例

```bash
curl.exe -X POST \
  "http://47.96.9.22:8765/api/customs/tasks/ct_63008f18bcaf4aa7/report-error" \
  -H "Authorization: Bearer <CUSTOMS_AGENT_TOKEN>" \
  -H "X-Agent-Name: finance-pc-01" \
  -H "Content-Type: application/json" \
  -d "{\"agentName\":\"finance-pc-01\",\"errorCode\":\"CARD_READ_FAILED\",\"message\":\"卡介质未连接或无法读取\",\"retryable\":true,\"reportedAt\":\"2026-10-29T13:24:33+08:00\"}"
```

## 7. 客户端接入

客户端已支持在 `config.local.json` 中配置失败接口后缀：

```json
{
  "error_endpoint_suffix": "/report-error"
}
```

当发生 `CARD_READ_FAILED` 等阻塞错误时，客户端会：

1. 保存本地 `data/runtime/card-error.json`。
2. 将本地任务状态置为 `blocked_card`。
3. 调用 `error_endpoint_suffix` 对应的接口。
4. 停止继续访问卡介质，等待人工恢复。

接口上线后只需把 `error_endpoint_suffix` 从空字符串改为 `/report-error`，不需要重新修改 Agent 代码。

## 8. 验收用例

1. 自有 `claimed` 任务上报 `CARD_READ_FAILED`，返回 `200`，状态变为 `blocked` 或 `failed`。
2. 重复上报同一任务，返回相同结果，不产生重复错误记录。
3. 其他 Agent 使用自己的 Token 上报，返回 `403`。
4. 已 `completed` 的任务上报，返回 `409`。
5. 不传文件、只传 JSON 错误原因，接口返回 `200`，不触发 PDF 解析。
6. 请求中包含卡口令或 Token 时，服务端日志不得记录请求体中的敏感字段。
7. 失败上报后，飞书或管理界面能够显示错误码、原因、Agent 和上报时间。

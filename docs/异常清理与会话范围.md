# 异常清理与项目范围（2026-09-22）

## 一、系统输入即拦截：历史遗留合同号

`app/services/scope.py` 统一判定「不在项目范围」的合同号，并在
**PDF 解析阶段**（`scripts/parse_customs.py`）与**拆单阶段**
（`scripts/run_split_knapsack.py`）各拦一道：

| 类型 | 例子 | 说明 |
| --- | --- | --- |
| CY / SP / ZY 开头的中间程序号 | `CY-26SM-S028`、`SP-08C2605`、`ZY20260508MT-XD` | 临时子公司 / 打样单 |
| 两位数字 + SM 开头 | `26SM-J135`、`25SM-A134` | 子公司 SM 系列 |
| 24 年及更早年份 | `24MT-08S522C` | 历史年份（25 年起在范围内） |
| 联合号里任意一段命中 | `25MT-06H520B&06K462B` | 按 `&`/`,` 拆开后逐段判定 |

被拦截的行不写入主结果，单独存到
`outputs/customs_parse/拦截_历史遗留合同号.xlsx`，并在解析统计里计数。

## 二、供应商全称/简称混用

`app/services/supplier_names.py` 用飞书供应商名录
（App `BV96bGPQSaXjt5s61YgcYqFpnMg`、Table `tblVRoMXPA5k7fhR`）做映射，支持：

- 全称 ⇄ 简称（`温州勇恒钢业有限公司` ⇄ `勇恒`）；
- 去掉 `-供应链`/`总部` 等内部后缀；
- **一条记录里塞了多家供应商**：`浙江希蒙雷斯钢管有限公司,浙江信得达特种管业`
  → `希蒙、信得达`；
- 名称被截断（少「有限公司」）时按包含关系唯一匹配。

比对时把 `希蒙、信得达` 拆成两个集合元素，避免"内容对但顺序/写法不同"误判。

## 三、出运单号分隔符不一致（新发现）

睿贝里同一张出运单会写成 `26MT-10E101-Y-A`、`26MT-10E101-Y A`（空格）、
`26MT-10E101-YA` 等。新增 `shipment_index.canonical()`：
去掉 `PI-` 前缀与所有分隔符（空格/连字符/下划线）后再比较。
修掉这一类后，「有 PDF 但没拆出」明显下降。

## 关于「飞书有而我没拆出」的一点更正

原先以为这批是"业务员肉眼录入、我们没有源 PDF 的旧数据"。
实测核对后：它们**绝大多数确实在我解析范围内**（我有对应 PDF），
只是拆单环节没产出。典型原因是出运单号分隔符写法不同（见第三节），
已修掉一批；剩余的属于"有源数据但组合凑不出/多解"。

# 财务电脑报关代理接口文档

## 1. 子项目职责

财务电脑上的程序只负责：

1. 轮询服务器任务队列并领取任务。
2. 根据本机保存的抓取进度，判断还需要从海关网站抓取哪些报关单。
3. 在财务电脑本地下载正式出口报关单和预录单 PDF。
4. 抓取耗时较长时续租任务。
5. 把本任务全部 PDF 一次性上传到服务器。
6. 查询任务处理状态，成功后推进本地抓取进度。

以下工作全部由服务器完成，财务电脑不要重复实现：

- 飞书任务创建
- PDF 文本解析
- 报关单拆单
- 采购成本匹配
- 创建飞书副本字段
- PDF 上传至飞书
- 正式 `2026报关记录 AI` 表写回
- 服务器 PDF 缓存清理

## 2. 基础信息

```text
Base URL: http://47.96.9.22:8765
认证方式: Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
数据格式: JSON，文件上传使用 multipart/form-data
建议轮询间隔: 10～30 秒
任务领取租约: 默认 900 秒
```

`CUSTOMS_AGENT_TOKEN` 只能存放在财务电脑的本地配置文件或操作系统环境变量中，不要写入源代码、日志、URL 或飞书请求。

服务端令牌配置位置：

```text
/opt/cost_matching_ultra/.env
CUSTOMS_AGENT_TOKEN=...
```

本机开发环境的令牌位于：

```text
E:\财务\cost matching\cost_matching_ultra\.env
CUSTOMS_AGENT_TOKEN=...
```

财务电脑只需要 `CUSTOMS_AGENT_TOKEN`，不需要飞书任务的创建令牌。

## 3. 状态机

```text
queued
  ↓ 财务电脑领取
claimed
  ↓ 上传完整 PDF 包
uploaded
  ↓ 服务器自动处理
processing
  ↓
completed

任一处理阶段失败：
failed

Agent 可上报的临时阻塞：
blocked
```

含义：

- `queued`：飞书已创建任务，等待财务电脑领取。
- `claimed`：财务电脑已领取，正在本地准备或下载 PDF。
- `uploaded`：完整 PDF 包已上传，等待服务器处理。
- `processing`：服务器正在解析、拆单、成本匹配或写回飞书。
- `completed`：飞书写回成功，任务结束。
- `failed`：任务失败，`error` 字段给出原因。
- `blocked`：发生可恢复故障，保留错误码和原因，等待人工恢复。

## 4. 无开始日期和结束日期

飞书创建任务时可以不传 `startDate` 和 `endDate`。

领取到的任务中可能出现：

```json
{
  "parameters": {
    "source": "feishu_button",
    "workflow": "customs",
    "flow": "both",
    "startDate": "",
    "endDate": "",
    "declarations": [],
    "contracts": []
  }
}
```

服务器不会根据当前日期自动推断抓取范围。财务电脑必须自行维护增量状态，例如：

```json
{
  "export": {
    "lastCompletedDeclaration": "224420260016128477",
    "lastCompletedDate": "2026-10-27",
    "lastTaskId": "ct_xxx"
  },
  "pre_record": {
    "lastCompletedDeclaration": "100000000000000001",
    "lastCompletedDate": "2026-10-27",
    "lastTaskId": "ct_xxx"
  }
}
```

实现要求：

- 正式出口单和预录单分别维护抓取进度。
- 下载时记录报关单号、PDF 文件哈希、下载时间和任务 ID。
- 只有服务器任务进入 `completed` 后，才推进对应流程的本地进度。
- 任务进入 `failed` 时不要推进本地进度，应保留失败任务信息并告警或下次重试。
- 同一 PDF 可以使用文件哈希去重，但不能只依赖文件名判断是否下载完成。

任务参数的使用规则：

- `flow=export`：只抓正式出口报关单。
- `flow=pre_record`：只抓预录单。
- `flow=both`：两类都要抓。
- `declarations=[]`：不按报关单号限制。
- `contracts=[]`：不按合同号限制。
- `declarations` 或 `contracts` 非空时，财务电脑应进一步限制到指定业务范围。
- 服务器只负责接收结果；财务电脑不能用空日期代替“从头抓全部”，也不能默认追加大范围历史数据。

## 5. 轮询领取任务

### 请求

```http
GET /api/customs/tasks/claim
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
X-Agent-Name: finance-pc-01
```

完整 URL：

```text
http://47.96.9.22:8765/api/customs/tasks/claim
```

`X-Agent-Name` 应是稳定的财务电脑标识。同一台电脑重启后继续使用相同名称。

### 没有任务

HTTP：

```text
200 OK
```

响应：

```json
{
  "hasTask": false,
  "task": null
}
```

客户端应等待下一个轮询周期，不应创建新任务。

### 领取成功

HTTP：

```text
200 OK
```

响应示例：

```json
{
  "hasTask": true,
  "task": {
    "id": "ct_0123456789abcdef",
    "state": "claimed",
    "createdAt": "2026-10-28T01:00:00+00:00",
    "updatedAt": "2026-10-28T01:00:05+00:00",
    "source": "feishu_button",
    "parameters": {
      "source": "feishu_button",
      "workflow": "customs",
      "flow": "both",
      "startDate": "",
      "endDate": "",
      "declarations": [],
      "contracts": []
    },
    "progress": 2,
    "message": "财务电脑已领取任务",
    "agentName": "finance-pc-01",
    "claimedAt": "2026-10-28T01:00:05+00:00",
    "leaseExpiresAt": "2026-10-28T01:15:05+00:00"
  },
  "uploadUrl": "/api/customs/tasks/ct_0123456789abcdef/upload",
  "statusUrl": "/api/customs/tasks/ct_0123456789abcdef",
  "heartbeatUrl": "/api/customs/tasks/ct_0123456789abcdef/heartbeat"
}
```

返回的相对 URL 都需要拼接到 Base URL 后使用。

## 6. 续租任务

如果下载全部 PDF 所需时间可能接近或超过 `leaseExpiresAt`，应定期续租，建议每 5 分钟一次。

### 请求

```http
POST /api/customs/tasks/{taskId}/heartbeat
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
X-Agent-Name: finance-pc-01
```

不需要请求体。

### 响应

```json
{
  "taskId": "ct_0123456789abcdef",
  "state": "claimed",
  "leaseExpiresAt": "2026-10-28T01:20:05+00:00"
}
```

注意：

- 只能续租自己领取的 `claimed` 任务。
- 其他电脑名称不能续租该任务。
- 续租失败时立即查询任务状态，不要继续盲目下载。

## 7. 上传 PDF

### 重要限制

服务器把一次上传视为本任务的完整文件包。当前接口不支持分片追加或第二次补传。

因此：

1. 必须先把本任务需要的 PDF 全部下载到本地临时目录。
2. 全部文件确认完整后再调用一次上传接口。
3. 一次请求中通过多个 `files` 字段上传全部 PDF。
4. 上传成功后服务器立即开始处理，不能再追加文件。

### 请求

```http
POST /api/customs/tasks/{taskId}/upload
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
X-Agent-Name: finance-pc-01
Content-Type: multipart/form-data
```

Multipart 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `agent_name` | 建议 | 应与 `X-Agent-Name` 一致 |
| `files` | 是 | PDF 文件，可重复出现多个 |

限制：

- 每个文件必须是 `.pdf` 且内容以 `%PDF-` 开头。
- 单文件默认不超过 20 MB。
- 单任务默认不超过 500 个 PDF。
- 单任务总大小默认不超过 500 MB。

### curl 示例

```bash
curl.exe -X POST \
  "http://47.96.9.22:8765/api/customs/tasks/ct_0123456789abcdef/upload" \
  -H "Authorization: Bearer <CUSTOMS_AGENT_TOKEN>" \
  -H "X-Agent-Name: finance-pc-01" \
  -F "agent_name=finance-pc-01" \
  -F "files=@D:/customs/a.pdf;type=application/pdf" \
  -F "files=@D:/customs/b.pdf;type=application/pdf"
```

### 成功响应

HTTP：

```text
202 Accepted
```

响应：

```json
{
  "taskId": "ct_0123456789abcdef",
  "state": "uploaded",
  "fileCount": 2,
  "statusUrl": "/api/customs/tasks/ct_0123456789abcdef"
}
```

## 上报任务阻塞或失败

卡介质拔出、无法读卡、登录超时等情况下，不调用 PDF 上传接口，改用：

```http
POST /api/customs/tasks/{taskId}/report-error
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
X-Agent-Name: finance-pc-01
Content-Type: application/json
```

请求体：

```json
{
  "agentName": "finance-pc-01",
  "errorCode": "CARD_READ_FAILED",
  "message": "卡介质未连接或无法读取",
  "retryable": true,
  "reportedAt": "2026-10-29T13:24:33+08:00",
  "details": {
    "vendorErrorCode": "50070",
    "phase": "login"
  }
}
```

要求：

- 请求头 `X-Agent-Name` 必须与 `agentName` 完全一致。
- `errorCode` 作为机器判断依据，`message` 只用于人工阅读。
- `reportedAt` 必须是带时区的 ISO 8601 时间。
- `retryable=true` 时任务变为 `blocked`；为 `false` 时变为 `failed`。
- 只有任务当前由该 Agent 领取且租约未过期时可以上报。
- 同一任务、同一 Agent、同一 `errorCode` 重复上报是幂等的。
- 已上传、处理中、已完成或其他 Agent 已上报的任务返回 `409`。
- `message` 和 `details` 中不得包含卡口令、Token、证书私钥等敏感信息。

成功响应：

```json
{
  "taskId": "ct_0123456789abcdef",
  "state": "blocked",
  "errorCode": "CARD_READ_FAILED",
  "message": "卡介质未连接或无法读取",
  "retryable": true,
  "errorReportedAt": "2026-10-29T13:24:33+08:00",
  "errorReceivedAt": "2026-10-29T13:24:35+08:00",
  "agentName": "finance-pc-01"
}
```

## 8. 查询任务状态

### 请求

```http
GET /api/customs/tasks/{taskId}
Authorization: Bearer <CUSTOMS_AGENT_TOKEN>
```

完整 URL：

```text
http://47.96.9.22:8765/api/customs/tasks/{taskId}
```

### 处理中响应

```json
{
  "id": "ct_0123456789abcdef",
  "state": "processing",
  "progress": 58,
  "message": "正在成本匹配",
  "parameters": {
    "flow": "both",
    "startDate": "",
    "endDate": ""
  }
}
```

### 成功响应

```json
{
  "id": "ct_0123456789abcdef",
  "state": "completed",
  "progress": 100,
  "message": "成本匹配 AI 表写回完成",
  "summary": {
    "declarations": [
      "224420260016128477"
    ],
    "pdfCount": 2,
    "aiRecords": 3,
    "uploadedFiles": 1,
    "resultFile": "result.json"
  },
  "cacheClearedAt": "2026-10-28T01:10:00+00:00",
  "cacheRemoved": [
    "uploads",
    "work"
  ]
}
```

### 失败响应

```json
{
  "id": "ct_0123456789abcdef",
  "state": "failed",
  "progress": 100,
  "message": "任务失败",
  "error": "ValueError: 1 份 PDF 解析失败：a.pdf: startxref not found",
  "cacheClearedAt": "2026-10-28T01:10:00+00:00",
  "cacheRemoved": [
    "uploads",
    "work"
  ]
}
```

失败后服务器仍会删除 PDF 和中间文件，因此不能通过旧任务继续补传文件，必须创建新任务重新抓取或上传。

## 10. HTTP 错误处理

| HTTP | 含义 | 客户端处理 |
|---|---|---|
| 200 | 领取或查询成功 | 正常处理 |
| 202 | PDF 已接收并开始处理 | 转入状态轮询 |
| 400 | PDF 格式错误或参数错误 | 不重试，记录错误并告警 |
| 403 | Agent Token 错误 | 停止调用，检查配置 |
| 404 | 任务或结果不存在 | 检查 Task ID |
| 409 | 任务已处理、状态冲突或已被其他电脑领取 | 查询状态，不要盲目重传 |
| 413 | 文件超过限制 | 拆分业务任务后重新创建任务 |
| 503 | 服务器未配置 Agent Token | 联系服务器管理员 |

网络超时后的处理：

- `claim` 超时：不要立即创建另一个任务；等待租约到期后重新领取。
- `heartbeat` 超时：重新查询任务状态。
- `upload` 超时：必须查询任务状态。若已是 `uploaded`、`processing` 或 `completed`，表示上传可能已成功，禁止立即重新上传；若仍为 `claimed`，可以重试同一个完整上传包。
- `status` 超时：按指数退避继续查询，不要改变任务。

## 11. 推荐的本地执行流程

```text
开始轮询
  ↓
GET /claim
  ↓ 无任务
等待 10～30 秒
  ↓ 有任务
保存 taskId 和参数
  ↓
读取本地增量状态
  ↓
确定待抓取报关单
  ↓
下载正式出口单/预录单 PDF 到本地临时目录
  ↓ 耗时超过 5 分钟
POST /heartbeat
  ↓
检查所有 PDF 完整、去重、数量正确
  ↓
一次性 POST /upload，上传全部 files
  ↓
每 5～10 秒 GET /status
  ↓
completed：推进本地抓取进度
  ↓
failed：不推进进度，记录错误并告警
  ↓
删除本地临时 PDF 或移入受控归档目录
```

## 12. 生产实现注意事项

- 不要硬编码 Agent Token。
- 不要在日志中打印 Token、Authorization 请求头或完整 PDF 内容。
- 正式环境建议服务器启用 HTTPS；当前联调地址为 HTTP。
- 同一台财务电脑应固定 `X-Agent-Name`。
- 不要把多个业务批次合并到同一任务上传，否则失败后需要整体重传。
- 上传前应校验文件确为 PDF、非空且大小在限制内。
- 需要保存任务的创建时间、领取时间、上传时间、状态和失败原因，便于补跑。
- 服务端只保留状态目录和结果文件，不保留上传的 PDF。

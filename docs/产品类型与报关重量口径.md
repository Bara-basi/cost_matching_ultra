# 产品类型回填 + 报关重量分摊 + 本地核对（2026-09-28）

本轮按用户口径做了三件事，并**只按本地系统能确定的事实**判定正常/异常（不与飞书对答案）。

## 1. 产品类型：统一成粗分类

背景：睿贝出运单界面的 `海关商品（中文）` 有时为空，导致拆单记录的产品类型缺失、
同一批货被并到不同记录里。

口径（用户 2026-09-28 确认）：

1. **主数据来源 = 产品编码 → 商品资料「类别名称」**（去掉部门括号，如
   `板棒(管道事业部)` → `板棒`）；抓取脚本 `scripts/fetch_product_categories.py`，
   缓存 `.cache/erp/details/products/<safe(产品编码)>.json`，读取见
   `app/services/product_master.py`。
2. 出运品名优先折算：`海关商品（中文）` 经 `data/reference/feishu_product_map.json`
   折算成粗分类（该文件是飞书「产品类型」表的镜像；同一个产品编码在睿贝里
   偶尔写错类别，实测三通的编码被标成法兰/管件混用，用出运品名能保留实际差异）。
3. 出运品名缺失时才用商品资料类别；再缺失用报关品名折算兜底。
4. 最终只落飞书那 10 类：`法兰 / 管件 / 无缝管 / 镍基无缝管 / 焊管 / 焊材 /
   板棒 / 盘管 / 三角丝 / 其他`（映射表没有的细分不再新增）。

`报关品名` 一列始终保留**报关单自己的品名**（不拿粗分类去覆盖），否则无法与主表对齐；
原先「混装报关」把报关品名改成实际品名的例外，现在只在实际品名本身是细分名时才生效。

求解器口径不变（`LEVELS` / `split_by_item` 仍以 ERP 出运品名为主键，
缺名时才用商品资料类别补位），因此**不改变已拆对的结果**，只把输出的
`产品类型` 列统一成粗分类。

## 2. 报关重量分摊

`拆单明细_全部.xlsx` 新增 `报关重量` 与 `重量分摊依据` 两列：

1. 报关行的重量没被拆（该行只出一条记录）→ 直接回填；
2. 被拆成多条记录、且各采购单的**入库单附件**能核到重量 → 按附件重量占比分摊；
3. 取不到附件重量 → 按**报关金额**占比分摊；最后一组吸收尾差。

保证「同一报关行的各条记录重量之和 = 报关单原件重量」（本地核对已验证，0 例外）。

## 3. 本地核对（不与飞书比对）

脚本 `scripts/build_local_review.py`，输出 `outputs/local_review/`：
`本地核对_全部.xlsx` / `本地核对_正常.xlsx` / `本地核对_异常.xlsx`。

判定依据全部来自本地：报关单解析结果、出运单明细、采购单入库单实发。检查项：

- 产品类型缺失 / 报关重量缺失；
- 睿贝未定价（出运采购金额(RMB)=0）；
- 未取得入库单实发金额；
- 报关金额恒等式 `出运金额合计 + 客户费用分摊 = 报关金额`；
- 报关单级「各行报关重量之和 = 报关单原件重量」；
- 出运数量 > 入库数量；
- 该采购单报关单不齐（我方货值 < 睿贝整单出运人民币）。

拆单阶段的本地未解决异常另见 `outputs/shipments_split/拆单_本地异常.xlsx`
（已人工核实的报关单不计入，它们在 `拆单结果_已核实.xlsx`）。

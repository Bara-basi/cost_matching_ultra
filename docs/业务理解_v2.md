# 成本匹配业务理解（v2 · 已按 FAQ 与 ERP 实测确认）

> v1 的五个待确认问题已在 `docs/faq_records/faq.md` 得到答复，
> 并通过睿贝 ERP 实测 + 历史项目 `../MT_cost_match_final` 交叉印证。
> 本文件是当前唯一有效的业务理解基线。

## 1. 目标与口径

把「报关单已解析记录」里的每条报关商品，反向从睿贝 ERP 找到它的采购成本，
按 `外销订单 → 产品类型 → 供应商` 多级拆分后，把金额分摊回每条记录并写回飞书多维表。
**用规则+模型取代现在的人工填写。**

成本真值来源 = **睿贝 ERP 的采购订单 / 出运单**。
（飞书「2026年报关数据」中已有的人工金额只作对照答案，绝不参与计算。）

## 2. 输入：飞书多维表格

- 目标表：「2026海关数据AI 副本」→ App `BV96bGPQSaXjt5s61YgcYqFpnMg` →
  表「2026年报关记录 AI」`tblm5OpiaC28eZ3P`（782 行 / 112 字段）。
- 一行 = **一张报关单上的一条商品**；`合同号` 来自报关单"合同协议号"（外销订单号）。
- 合同号规范见 `docs/合同号规范.md`：`26MT-0KXXXX` + 可选 `Y`（有佣金）+ 可选 `ADD`（附加单）。

### 2.1 必须跳过的行（不进入匹配）

| 情形 | 判定 | 行数 |
| --- | --- | --- |
| 内销 / 预录订单 | `报关单号` 为空（财务按栏位分流的另一类数据） | 111 |
| 明显不合规范的合同号 | 前缀为 `DP`/`SP`/`ZY`/`CY`/`XM`/`SM` 等中间程序号 | 37 个合同号 |
| 24 年历史单、零成本样品单 | `24MT-` 开头、样品单规则 | 少量 |

剔除后剩余 **671 行**，即本期真正要计算的外销报关商品行
（与「报关数据」表中带报关单号的 671 行一致）。

### 2.2 关于无附件的行

多行没有 PDF 附件，是因为数据被污染：早期是人工录入；现在表里是财务在脚本结果上
继续做了拆单与成本匹配的产物。因此**这张表现有结果是我们 output 的参考样例，不是纯 input**。
系统仍要读它，原因有二：① 将来新提取的数据会成为真实输入，输出格式要对齐；
② 要理解各字段含义（如 `合同号_1` = 报关单上的合同号，通常就是出运单号）。

## 3. 关键字段与公式链（副本表）

### 3.1 人工/脚本需写入的字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 采购金额 | Number | **唯一需要写入的成本字段**，来自 ERP 采购金额分摊 |
| 报关金额 | Number | 报关金额（外销发票口径） |
| 报关重量 | Number | 报关数量/重量 |

### 3.2 公式字段（写入采购金额后自动计算）

| 字段 | 公式 |
| --- | --- |
| 实际成本 | 采购金额 + 调整（原材料）少"+"，多"-" |
| 不含税成本 | 采购金额 / 1.13 |
| 开票金额 | 采购金额 + 调整金额 |
| 整单毛利 | 按 `报关单号` 聚合不含税收入与成本 |
| 不含税人民币收入、销项税额、退税额、应纳税额、毛利率等 | 公式 |

> 主表 `tblXCun7DWTZ4Iow` 的 `采购金额` 被改成 Lookup（从「2026年报关数据」取数），
> 副本表则是可写的 Number 字段——这正说明副本表是我们要写入的目标。

## 4. ERP 数据结构（实测）

ERP MCP 服务：`https://erp.mtholdinggroup.com/AgentServerSimple/mcp`（Bearer `ERP_API_KEY`，
限速 1 请求/秒）。核心工具：`sale_order.find` / `shipment.find` / `purchase.find`。

### 4.1 外销订单 `sale_order.find(orderCode=PI-xxMT-...)`

`orderBaseInfo`（销售订单号带 `PI-` 前缀、客户、价格条款、订单金额、汇率）+
`productList`（产品编码、单价、数量、金额、产品类别、海关商品、**成本单价**）。

### 4.2 出运单 `shipment.find(invoiceCode=PI-xxMT-...)`  ★成本事实所在

`shipmentBaseInfo`（外销发票号、出运日期、出运总金额、折RMB金额）+ `expenseList` +
`productList`，每行含：

| 字段 | 示例（25MT-05G616） |
| --- | --- |
| 采购订单号 | `25MT-05G616-YH` / `25MT-05G616-HD` |
| 供应商编码 | `S2412260001`（勇恒） / `S2412270004`（鸿迪） |
| 出运采购金额(RMB) | `7800.00` / `20000.00` |
| 采购单价(RMB)、出运数量、已入库数量 | `7800.00000` / `1.0` |
| 产品编码、海关商品（中文）、海关编码 | `P25111762` / `镍合金管件` / `7507200000` |
| 外销单价、出运金额、订单数量 | `1276.12` / `1276.12` / `1.0` |

### 4.3 采购订单 `purchase.find(purchaseCode=25MT-05G616-YH)`

`purchaseBaseInfo`（采购单号、供应商名称、总数量、**总金额**、折RMB金额、付款状态）+
`productList`（产品编码、数量、单价、金额、已入库数量）。

实测：`25MT-05G616-YH` 总金额 = `15650.00`，恰等于该出运单中三条勇恒行的
`7800 + 3200 + 4650`。**采购单号是成本归属的天然单位。**

## 5. 拆单与分摊规则

最小业务单位（一行输出）= `合同号(外销订单) + 产品类型 + 供应商`，金额落到每条报关商品行。

1. **定位**：用 `合同号` 查 ERP 出运单（同一合同号通常就是同一张出运单；一次出运含多单时为
   `&` 连接的联合号，按 `docs/合同号规范.md` 展开）。
2. **取成本事实**：出运单 `productList` 逐行给出 `采购订单号 / 供应商 / 出运采购金额(RMB) / 产品类型`。
3. **按采购订单归集**：同一采购订单号的产品行金额汇总为该采购订单成本。
4. **按产品类型拆分**：采购订单内按产品类型分组（类型判定见 §6）。
5. **按重量分摊到报关行**：组内金额按各报关行的报关重量比例分摊，最后一行吸收分位尾差。
6. **写回**：`采购金额` 写分摊结果，`报关金额`、`报关重量` 同步写回；其余公式字段自动计算。

> 已实测样例（25MT-05G616）：出运单 4 条产品行 = 勇恒 3 条（7800+3200+4650=15650）
> + 鸿迪 1 条（20000）；报关记录 2 行（法兰 49kg→15650、管件 41kg→20000），
> 与人工参考完全一致。

## 6. 产品类型判定

以 `docs`+历史项目 `map.md`（海关品名 → 产品类型，89 条/10 类）为主，
ERP 出运行的 `海关商品（中文）` 与报关行 `报关品名` 交叉校验；英文关键词按**词边界**匹配
（历史教训：`tee` 会误命中 `steel`，把不锈钢管误判为管件）。

## 7. 工程架构

```
飞书多维表格（源）
   │ ① 读取报关记录（含合同号/报关单号/品名/重量/金额）
   ▼
拆分服务  FastAPI  app/services/
   │ ② 跳过内销/预录/异常合同号
   │ ③ 调 ERP MCP：sale_order.find → shipment.find → purchase.find
   │ ④ 按 外销订单→产品类型→供应商 拆分，按重量分摊
   ▼
⑤ 写回飞书：采购金额 / 报关金额 / 报关重量（公式字段自动算）
   ▼
Vue 前端：任务触发、进度、结果预览、异常清单
```

已落地：`app/services/feishu_client.py`（飞书鉴权/读写）、`app/services/erp_client.py`（ERP MCP 客户端）。
